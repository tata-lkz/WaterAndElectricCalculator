MQTT Viewer - Cloud version (Render.com)

Build Command : npm install
Start Command : npm start
Node          : 18 ขึ้นไป

ถ้าตั้ง Render Runtime เป็น Docker ระบบจะใช้ Dockerfile ที่ root ของโปรเจกต์แทนคำสั่งด้านบน

โครงสร้างไฟล์ (ต้องเป็นแบบนี้ใน GitHub)
  server.js  datalog.js  package.json
  public/index.html  public/login.html
  public/manifest.webmanifest  public/sw.js  (ไฟล์ติดตั้งเป็นแอปบนมือถือ)
  public/icon-192.png  public/icon-512.png  public/icon-maskable-512.png  public/apple-touch-icon.png
  (ถ้าวาง index.html / login.html ไว้ข้าง server.js ก็ยังเปิดได้ แต่แนะนำให้อยู่ใน public/)

Environment variables
  MQTT_URL    = mqtt://thaiplc.thddns.net:6062
  MQTT_USER   = (your broker user)
  MQTT_PASS   = (your broker password)
  APP_PASS    = (password for opening the website)  <-- required, pick a strong one
                (ถ้าไม่ตั้งบน Render/production แอปจะไม่ยอมเริ่มทำงาน ตั้ง ALLOW_NO_PASS=1 ถ้าตั้งใจเปิดสาธารณะ)
  APP_SECRET  = (optional) ข้อความสุ่มยาวๆ ใช้ทำโทเค็นล็อกอิน เปลี่ยนค่านี้เพื่อเตะทุกเครื่องที่ล็อกอินค้างอยู่ โดยไม่ต้องเปลี่ยนรหัสผ่าน
  TRUST_PROXY_HOPS = 1    จำนวนชั้นพร็อกซีหน้าแอป (ใช้หา IP จริงเพื่อจำกัดการลองรหัสผ่าน; มี Cloudflare หน้า Render ให้ลองใส่ 2)
  MQTT_TOPICS = Water/Meter/Value,demo/data/#        (optional)
  MAX_KEYS    = 500       จำนวน topic / ชื่อค่าสูงสุดที่รับ (กันหน่วยความจำโตไม่จำกัด)

  --- กราฟ (optional) ---
  HISTORY_HOURS = 24      เก็บประวัติย้อนหลังกี่ชั่วโมง
  HISTORY_GAP_S = 10      เก็บจุดกราฟห่างกันอย่างน้อยกี่วินาที
  HISTORY_MAX   = 10000   จำนวนจุดสูงสุดต่อ 1 ค่า

  --- Telegram (optional) ---
  TG_TOKEN    = โทเคนบอทจาก @BotFather
  TG_CHAT     = chat id (ส่งข้อความ /id หาบอทเพื่อดูเลข, ใส่หลายแชทคั่นด้วย ,)
  TG_TIMES    = 08:00,18:00     เวลาส่งรีพอร์ตอัตโนมัติ
  TG_TZ       = Asia/Bangkok
  TG_HOURS    = 24              รีพอร์ตสรุปย้อนหลังกี่ชั่วโมง
  TG_CHARTS   = 8               จำนวนกราฟที่แนบต่อรีพอร์ต (0 = ไม่แนบ)
  TG_POLL     = 0               ใส่ 0 ถ้าไม่ต้องการรับคำสั่ง /report
  TG_ONLY     = กระแส,power     (optional) รีพอร์ตอัตโนมัติ/คำสั่ง /report ส่งเฉพาะค่าที่ชื่อมีคำเหล่านี้

  --- แจ้งเตือนขาดการติดต่อ (optional, ต้องตั้ง TG_TOKEN + TG_CHAT) ---
  WATCH_MIN        = 5    อุปกรณ์ (topic) ไม่ส่งข้อมูลเกินกี่นาทีถึงแจ้ง (0 = ปิดการเฝ้าอุปกรณ์ ยกเว้นที่ระบุใน WATCH_RULES)
  WATCH_RULES      = water=30,demo/data=3,test=0   กำหนดเวลาแยกตามชื่อ topic (ชื่อมีคำนี้ = ใช้เวลานี้ / 0 = ไม่เฝ้า)
  WATCH_BROKER_S   = 60   เซิร์ฟเวอร์ต่อ broker ไม่ได้เกินกี่วินาทีถึงแจ้ง (0 = ปิด)
  WATCH_REPEAT_MIN = 0    เตือนซ้ำทุกกี่นาทีถ้ายังไม่กลับมา (0 = แจ้งครั้งเดียว แล้วแจ้งอีกทีตอนกลับมา)
  - แจ้งทั้งตอนหาย และตอนกลับมา (บอกว่าหายไปนานเท่าไร) ถ้าหลายตัวหายพร้อมกันรวมเป็นข้อความเดียว
  - ตอน broker หลุด จะไม่ตัดสินว่าอุปกรณ์เงียบ และหลังต่อใหม่จะเริ่มนับเวลาใหม่ กันแจ้งผิด
  - ถ้าส่ง Telegram ไม่สำเร็จ จะลองใหม่เองทุก 15 วินาที
  - พิมพ์ /status ในแชท Telegram เพื่อดูสถานะ broker และอุปกรณ์ทุกตัว (ต้องไม่ตั้ง TG_POLL=0)
  - ข้อจำกัด: เฝ้าเฉพาะ topic ที่เคยส่งข้อมูลมาตั้งแต่เซิร์ฟเวอร์เริ่มทำงาน ถ้าอุปกรณ์ดับก่อนรีสตาร์ท/ดีพลอยใหม่
    จะไม่ถูกรู้จักจนกว่าจะส่งข้อมูลมาอีกครั้ง

  --- เก็บข้อมูลย้อนหลังถาวร (optional แต่แนะนำ) ---
  DATABASE_URL  = connection string ของ Postgres (Neon / Supabase)
  LOG_DAYS      = 90      เก็บกี่วัน เกินแล้วลบเอง
  LOG_FLUSH_MIN = 0       0 (ค่าเริ่มต้น) = เขียนลงฐานข้อมูลทันทีทุกข้อความ MQTT; มากกว่า 0 = บันทึกเป็นรอบนาที (เช่น 1 หรือ 15)
  LOG_ROLLUP_DAYS = 7     ข้อมูลเก่ากว่ากี่วันให้ย่อเป็นรายชั่วโมง (0 = ไม่ย่อ เก็บรายนาทีตลอด)
                          ย่อแล้วขนาดลดราว 60 เท่า กราฟ/ตารางสรุป/ค่าเฉลี่ยยังใช้ได้เหมือนเดิม (ค่าเฉลี่ยถ่วงน้ำหนักตามจำนวนตัวอย่าง)
                          สิ่งที่เปลี่ยน: ข้อมูลเก่ากว่านี้ซูมดูละเอียดกว่ารายชั่วโมงไม่ได้ และ CSV ของช่วงเก่าจะเป็นแถวละ 1 ชั่วโมง
                          (ค่า เฉลี่ย/ต่ำสุด/สูงสุด/ล่าสุด ของชั่วโมงนั้นยังครบ) ระบบทำเองตอนเริ่มและทุก 6 ชั่วโมง ไม่ต้องสั่ง SQL
  DB_SSL_VERIFY = 1/0     (optional) 1 = ตรวจใบรับรอง SSL เต็มรูปแบบ, 0 = เข้ารหัสแต่ไม่ตรวจ
                          ค่าเริ่มต้น: ใช้ Neon = ตรวจให้อัตโนมัติ / ที่อื่น (เช่น Supabase) = ไม่ตรวจ (ถ้าตรวจแล้วเจอ error ใบรับรอง ให้ตั้ง 0)
                          (ระบบตัด ?sslmode=... ออกจาก DATABASE_URL ให้เอง จึงไม่เจอ error self-signed certificate)
  เมื่อเปิดใช้ฐานข้อมูล กดการ์ดเพื่อเปิดกราฟใหญ่ จะมีตัวเลือก "ดูย้อนหลังจากฐานข้อมูล" 1/7/30/90 วัน พร้อมตารางสรุปรายวัน

หน้า Datalog (ปุ่ม 📒 Datalog ด้านบนของหน้าเว็บ)
  - ระบบบันทึกทุกค่าลงฐานข้อมูลเองทันที (เก็บสถิติเป็นรายนาที) ไม่ต้องมีใครเปิดหน้าเว็บค้างไว้ ต้องตั้ง DATABASE_URL
  - ตารางสรุปทุกค่า: ล่าสุด/ต่ำสุด/สูงสุด/เฉลี่ย และช่วงข้อมูลที่เก็บไว้ (ค่าที่ระบบรู้จักเช่นไฟฟ้า/อุณหภูมิขึ้นก่อน ติ๊ก "เฉพาะค่าสำคัญ" เพื่อซ่อนค่าอื่น)
  - ถ้าฐานข้อมูลล่มหรือกำลังตื่น จะมีแถบเตือนสีเหลือง ข้อมูลที่ค้างอยู่ในเซิร์ฟเวอร์จะถูกเขียนให้เองเมื่อฐานข้อมูลกลับมา
  - ปุ่ม "บันทึกตอนนี้" เขียนค่าที่ค้างในหน่วยความจำลงฐานข้อมูลทันที (โหมดปกติเขียนทันที; ตั้ง LOG_FLUSH_MIN ให้มากกว่า 0 เพื่อเปลี่ยนเป็นบันทึกเป็นรอบ)
  - ⬇️ CSV ดาวน์โหลดข้อมูลรายนาทีของค่านั้น (เปิดใน Excel ได้ ภาษาไทยไม่เพี้ยน)
  - 🗑️ ล้างข้อมูลของค่าเดียว หรือ "ล้างทั้งหมด" (ต้องพิมพ์ RESET ยืนยัน) กู้คืนไม่ได้ และจะล้างกราฟบนหน้าเว็บให้เริ่มนับใหม่ด้วย
  - ถ้าใช้ Render แพ็กเกจฟรี เซิร์ฟเวอร์หลับเมื่อไม่มีคนเข้าเว็บ ช่วงที่หลับจะไม่มีการบันทึก ให้ตั้ง UptimeRobot ยิง /healthz ทุก 5 นาที

ตั้งค่าเก็บข้อมูลด้วย Neon (ฟรี)
  1) สมัคร neon.com -> Create project (เลือก Region ใกล้ไทย เช่น Singapore)
  2) กด Connect -> คัดลอก connection string (ขึ้นต้น postgresql://...)
  3) รันในเครื่อง: สร้างไฟล์ `.env` ที่โฟลเดอร์โปรเจกต์ แล้วใส่ `DATABASE_URL="postgresql://..."` (ห้าม commit ไฟล์นี้)
     บน Render: Environment -> เพิ่ม DATABASE_URL = ข้อความที่คัดลอก -> Save (จะ deploy ใหม่เอง)
  4) ดู Logs ต้องเห็น "[db] โหลดประวัติ ..." และเมื่อมีข้อความ MQTT จะเห็น "[db] บันทึก ... แถว"
  - ตารางสร้างให้เองอัตโนมัติ ไม่ต้องสั่ง SQL
  - ใช้ Supabase ได้เหมือนกัน: ใส่ connection string แบบ Session pooler (IPv4)

หน้าเว็บ: มุมมองและการจัดหน้า (ตั้งค่าในเบราว์เซอร์ของแต่ละคน ไม่ต้องตั้งอะไรที่เซิร์ฟเวอร์)
  - แถบด้านบนสลับมุมมองได้ 3 แบบ: ▦ การ์ด (ใหญ่ มีกราฟละเอียด) / ▤ กระชับ (การ์ดเล็ก กราฟเส้นเล็ก เห็นได้มากขึ้น) / ☰ ตาราง (ทุกค่าในตารางเดียว)
  - 📌 บนการ์ด/แถวตาราง = ปักหมุดให้ไปอยู่กลุ่ม "ปักหมุดไว้" บนสุด   🙈 = ซ่อนค่านั้น (ปุ่ม "ซ่อนอยู่ N ค่า" ด้านบนใช้เอาค่าที่ซ่อนกลับมา)
  - ที่ปักหมุด/ซ่อน/มุมมองที่เลือก จำไว้ในเครื่องนั้นๆ (localStorage) แต่ละคนจัดหน้าของตัวเองได้ ไม่กระทบคนอื่น และไม่ได้ลบข้อมูลจริง
    (ส่งรีพอร์ต Telegram และการบันทึกลงฐานข้อมูลยังทำงานกับทุกค่าตามเดิม)

ติดตั้งเป็นแอปบนมือถือ/คอมพิวเตอร์ (PWA)
  - Android (Chrome): เปิดเว็บแล้วกดปุ่ม "📲 ติดตั้งเป็นแอป" ด้านบน หรือเมนู ⋮ -> ติดตั้งแอป
  - iPhone (Safari): กดปุ่มแชร์ -> "เพิ่มลงหน้าจอโฮม"  (iOS ไม่มีปุ่มติดตั้งอัตโนมัติ)
  - ต้องเปิดผ่าน https (Render ให้อยู่แล้ว) และต้องมีไฟล์ใน public/ ครบตามด้านบน
  - แอปไม่เก็บแคชข้อมูล (ข้อมูลเป็นแบบสดและอยู่หลังรหัสผ่าน) ถ้าต่อเซิร์ฟเวอร์ไม่ได้จะขึ้นหน้า "เชื่อมต่อไม่ได้" พร้อมปุ่มลองใหม่
  - ถ้าเปลี่ยนไอคอน ต้องลบแอปแล้วติดตั้งใหม่ถึงจะเห็นไอคอนใหม่

ใช้งาน Telegram
  1) คุยกับ @BotFather -> /newbot -> ได้ TG_TOKEN
  2) กดเริ่มคุยกับบอทของคุณ แล้วพิมพ์ /id -> ได้ TG_CHAT (กลุ่มก็ได้: เพิ่มบอทเข้ากลุ่มแล้วพิมพ์ /id)
  3) ในแชทพิมพ์ /report หรือ /report 6 (ย้อนหลัง 6 ชม.) เพื่อขอรีพอร์ตทันที
     หรือกดปุ่ม "ส่งรีพอร์ตเข้า Telegram" บนหน้าเว็บ

ข้อควรระวัง
  - ถ้าไม่ตั้ง DATABASE_URL ประวัติกราฟเก็บในหน่วยความจำ รีสตาร์ท/ดีพลอยใหม่แล้วเริ่มนับใหม่ (ตั้งแล้วจะไม่หาย)
  - Render แพ็กเกจฟรีจะหลับเมื่อไม่มีคนเปิดเว็บ ทำให้รีพอร์ตตามเวลาไม่ออก และประวัติหาย
    แนะนำให้ใช้ UptimeRobot ยิงมาที่ https://<ชื่อแอป>.onrender.com/healthz ทุก 5 นาที
  - ห้ามรันหลายเครื่องพร้อมกันด้วย TG_TOKEN เดียวกัน (รีพอร์ตจะซ้ำ และรับคำสั่งชนกัน) ให้ตั้ง TG_POLL=0 ในเครื่องที่ไม่ใช่ตัวหลัก
